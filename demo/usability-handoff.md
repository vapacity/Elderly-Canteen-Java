# 长者食堂可用性测试交接单

受测场景是老年用户在手机浏览器订一顿送到家的午餐，并判断订单是否已提交。测试使用演示库和模拟余额。入口为 [手机点餐](http://116.62.84.213/mobile/)。测试组可从 [网页首页](http://116.62.84.213/) 核对日期和菜单。代码及启动方式见 [演示说明](README.md)。正式开测当天填写版本提交号、浏览器、设备型号和测试时间，所有参与者使用同一受测版本。

参与者只需要进入手机端密码登录。账号及普通密码由项目负责人通过小组渠道交接，账号与匿名编号的对应表由主持人保管。测前登录进入首页，并检查购物车为空。主任务每人一个账号，异常场景账号分开使用。

| 条件 | 账号或起点 | 给主持人的验证点 |
| --- | --- | --- |
| A 正常下单 | 21–30，即 `19900000021` 至 `19900000030`。每人初始余额 120 元，已有一个虚构默认地址 | 按相同任务下单，使用任务单给的新地址，确认订单和支付结果 |
| B 余额不足 | 10。余额 1 元，选一份 2 元的白米饭 | 提交会提示余额不足。仍在结算流程，购物车保留，余额和库存不变。本场结束后清空购物车 |
| C 库存不足 | 单独使用另一个空购物车。「香菇蒸鸡」当天初始库存 1 份 | 尝试选 2 份，记录实际反馈和数量是否停在 1。验证完清空购物车，避免提交消耗共享库存 |
| D 无默认地址 | 13。余额 120 元，地址为空 | 留空尝试提交，提示「请填写配送地址」。填入虚构地址后可继续。公共地址测试保持「设为默认地址」未选中，供后续场次复用 |
| 内部预试 | 11，可能已有历史订单 | 检查设备、任务单、计时和记录方式。预试单独归档 |

B、C、D 建议放在主任务之后，或作为单独的补充场次。校对题目时可观察「爱心外卖」入口和结算页「取餐地址」用词，以及「显示更多」是否容易发现、错误反馈是否被注意到。记录参与者实际经历了哪些场景。B、D 如果复用账号，主持人先核对购物车、余额和默认地址，再让下一位参与者开始。案例 C 开测前可从管理台核对库存，不消耗该菜的库存。

## T1–T5 主任务草案

主持人预先完成密码登录，从手机首页开始。将任务卡中的小目标分段读出，让参与者自己寻找入口和操作。示例地址「同济新村测试楼 203 室」为虚构地址。

| 任务 | 读给参与者的目标 | 主持人判定依据 |
| --- | --- | --- |
| T1 | 想让食堂把午饭送到家，请开始订餐。 | 进入外送菜单，未误选堂食 |
| T2 | 想吃一份红烧鸡腿、一份清炒小青菜和一份白米饭，请选好。 | 购物车中正好有这三样，各 1 份 |
| T3 | 家人也要吃饭，请把米饭改成两份，并核对买了什么。 | 鸡腿 1、青菜 1、米饭 2，当前菜单下合计 22 元 |
| T4 | 把午饭送到「同济新村测试楼 203 室」，并完成下单。 | 成功创建一笔外送订单，地址和菜品正确，使用模拟余额 |
| T5 | 请找到刚才的订单，说说现在是什么状态。 | 找到正确订单，能说明「订单已提交，正在等接单」 |

T1–T5 连续执行。若某一步无法继续，先记录该步结果和耗时，再由主持人恢复到下一步的起点。备注后续任务有无使用恢复起点。任务卡措辞、计时起止点和成功标准由测试组在预试后统一。
