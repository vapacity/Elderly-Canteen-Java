# 长者食堂：外送订餐复现

正式前端取自两个仓库的 `release` 分支。Java 后端以 `main` 为基础；复现修改都在各仓库的本地 `usability-demo` 分支。Java 的 `demo` profile 启用兼容接口和独立文件数据库，前端请求与页面同源。原先的 Java 安全实验分支不用于此次部署。

| 环境 | 网页端 | 手机浏览器 |
| --- | --- | --- |
| 本地 | http://127.0.0.1:18080/ | http://127.0.0.1:18080/mobile/ |
| 服务器 | http://116.62.84.213/ | http://116.62.84.213/mobile/ |

## 测试账号

进入手机端，选择密码登录；分配不同账号以免参与者互相影响。所有地址、余额、订单及菜品数据均为演示数据，填写地址时请使用虚构地址。

- `19900000001` 至 `19900000009`：每人初始余额 120 元。
- `19900000010`：余额 1 元，可验证支付失败及恢复。
- `19900000011`：供内部验证使用，可能已有测试订单。
- 本地密码见 `data/demo.env` 的 `CANTEEN_DEMO_PASSWORD`；服务器密码由部署负责人单独分发，见服务器 `/etc/canteen-demo.env` 的同名字段。两份数据库和密码独立。
- 「香菇蒸鸡」当天初始库存 1 份。验证库存不足可在同一购物车尝试选第 2 份。正式参与者不要共用库存仅有一份的菜作为成功任务的必选项。

推荐主路径：爱心外卖 → 选菜 → 查看购物车，修改数量 → 去结算 → 核对地址 → 立即下单 → 支付 → 我的订单 → 进入详情查看状态。余额不足应停留在结算页并保留购物车。

网页端用于查看食堂主页、菜单及密码登录。短信、注册、语音、志愿者接单、管理后台和实际配送、支付不在本次复现范围。外送单完成支付后停在「待接单」。本版本未接入参与者事件日志导出。

## 本地重启和重新构建

三个仓库目录放在同一级，使用各自的复现分支。需要 Java 17 或 21、Maven、Node 22 和 Python 3。Java 后端默认只绑定本机回环地址。

```sh
# 在 Elderly-Canteen-Demo 根目录
export JAVA_HOME=$(/usr/libexec/java_home -v 21) # macOS 示例
mvn -B -DskipTests package
./demo/build-assets.sh
./demo/start-local.sh
```

本地启动终端按 Ctrl+C 停止。数据库在 `data/canteen.mv.db`。正常重启保留测试订单和余额；菜单随上海时间切换。正式测试前应分配干净账号，勿拿内部验证账号作为参与者账号。

验证（会使用专用账号 10、11，并创建一笔验证订单）：

```sh
set -a; source data/demo.env; set +a
python3 demo/smoke.py http://127.0.0.1:18080
```

## 服务器

服务器内安装 Java 17 和 Nginx 后，使用已配置 SSH 密钥的账号运行 `./demo/deploy.sh`。Nginx 提供前端并只转发 `/demo-api/`；后端使用 systemd 服务 `canteen-demo`，数据在 `/var/lib/canteen-demo/data`。服务开机启动；排查启动问题可用 `journalctl -u canteen-demo -n 80`。本次使用 HTTP 和虚构账户，适合课堂演示。
